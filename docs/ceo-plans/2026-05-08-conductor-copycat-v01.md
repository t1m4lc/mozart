## Architecture Decision
**Dropped NestJS sidecar.** Pure Tauri Rust backend:
- `tauri-plugin-sql` (SQLite natively in Rust)
- `worktree.rs` (Rust Command::new("git"))
- `llm.rs` (reqwest → Claude streaming API)
- `keyring` crate (OS keychain: macOS Keychain / Windows Credential Manager / Linux Secret Service — use directly, no Tauri plugin wrapper needed)
- Angular + Spartan NG (shadcn/ui port, dark theme)

No port management. No IPC handshake. No Node.js runtime. One process.

## Business Model
Conductor.build is FREE — users bring their own Claude keys. Same model.
v0.1: free, no auth, no billing, no backend. Ship fast.
Monetize at 200+ users based on what users say they'd pay for.

## Concurrency Model
Each agent = a spawned Rust async task (`tokio::spawn`) calling Claude streaming API.
stdout tokens → Tauri `Channel<String>` → Angular component updates live.
Max 4 concurrent tasks. Status tracked in SQLite agents table.

## API Key Flow
1. First launch: Angular `SettingsComponent` prompts for Claude API key
2. Key stored via Rust `keyring` crate (OS-native, no plaintext)
3. On subsequent launches: keyring reads key silently; no prompt
4. Key rotation: settings screen lets user update/delete

## Error Handling Policy
| Error | Action | User sees |
|-------|--------|-----------|
| git not on PATH | Startup check fails | Dialog with install link |
| git worktree conflict | status="conflict" in DB | "Resolve conflict" badge in UI |
| Claude API 429 | Exponential backoff, 3 retries | status="rate-limited" |
| Claude API 5xx | status="error", store message | "Retry" button |
| Streaming disconnect | status="error" | "Retry" button |
| keyring unavailable | Fall back to env var | Warning in settings |

## Code Signing Clarification
- **v0.1**: NO signing. Document user workaround: macOS "right-click → Open", Windows "More info → Run anyway"
- **v0.2**: Implement signing. macOS: Apple notarization ($99/yr). Windows: EV certificate (~$200–$500/yr).
