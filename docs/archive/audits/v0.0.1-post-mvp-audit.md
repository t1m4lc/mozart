# Mozart — Post-MVP audit (v0.0.1)

**Date :** 2026-05-16
**Auditor :** Claude Code, Opus 4.7 (Max effort)
**Methodology :** code reading only, no app execution. Cross-checked
each Phase 1-6 demoable assertion in `done.md` against the actual
code under `apps/desktop`, `apps/web`, and `libs/ui`.

---

## Executive summary

- **MVP demoable assertions** : 49 / 56 verified ✅, 5 ⚠️ (drift but
  functional), 2 ❌ (broken / missing). Core flows ship.
- **Spec drift** : 18 entries, most concentrated on the Composer
  (Signal Forms migration deferred), Settings (duplicate
  "Connections" header), and Workspace toolbar (Open in IDE +
  Commit + PR all live in the right aside instead of the central
  top bar).
- **Architectural debt** : essentially **clean** — zero violations
  on six of seven greps. Tauri imports stay in `/data/` and
  `/core/`; `libs/ui` imports zero domain runtime; no template
  forms; no localStorage in desktop auth. One soft violation : the
  Composer textarea still uses `ngModel` instead of Signal Forms.
- **User remarks** : 22 distinct items captured from §3. All
  reproduced through code reading except the two that depend on
  visual polish judgement (workspace empty state hierarchy, modal
  spacing). 4 are blockers, 11 majors, 7 minors.
- **Phase 7 readiness** : **GO with one prerequisite**. Fix
  IMP-001 (project filter resets after filtering — the Visible
  Projects bug) before starting the refactor, because the
  ProjectsFacade signal shape is touched by the refactor and the
  fix changes the contract. Everything else can ride along Phase 7
  cleanly.
- **Recommended next action** : run the 4 blockers in a single
  Phase 6.5 patch pass (½ day) so Phase 7 starts on a clean store,
  then bundle Composer simplification + dialog harmonization with
  the Phase 7 refactor itself.

## A4 — Performance + UX feel

Read-only review. No profiling.

### Perf concerns

1. **`feature-chat-panel.ts:115` `_anchorVisible` is updated on every IntersectionObserver tick** — the observer fires often during smooth scrolls. Already debounced (`SCROLL_SETTLE_MS=220`) before propagating to `autoFollowChat`, so impact is bounded.
2. **`chat.facade.ts:100-106` `streamingChatIds`** iterates every message on every dependency change. For typical chats (<100 messages) negligible ; ten thousand-message chats would feel sluggish.
3. **`shell-project-list.ts:228-238` `workspacesByProject`** rebuilds the map from scratch on every workspaces signal change. Fine for v0.0.1 workspace counts (tens, not thousands).
4. **No `cdk-virtual-scroll` anywhere.** `message-list.ts` renders all messages flat ; long chats will pay for it. Spec §3.2 of composer doc called for `cdk-virtual-scroll-viewport`. **Drift.**
5. **`add-project.flow.ts` likely contains N+1 calls** (folder existence checks, git status probes) — not opened in this audit, flagged for Phase 7 cleanup.
6. **`requestAnimationFrame` chained with `setTimeout(500ms)`** in `feature-chat-panel.ts:265-279`. The suppression flag is awkward but the comment explains the rationale. Worth a Phase 7 simplification pass.

### UX concerns

1. **`prefers-reduced-motion` is only honored on the smooth-scroll into the anchor.** Toaster slide-in, composer overlay button fade, sidebar resize transition, dialog open/close animations — none gate on it. Spec required it across the board. **Drift.**
2. **`chat-empty-state.ts` 'start' variant renders a 5-item vertical checklist.** Lots of vertical space, multiple icons, mixed colors. User remarked "trop d'informations, manque de hiérarchie".
3. **Workspace toolbar lacks any action buttons** beyond Toggle Right Sidebar. The user expected Open in IDE there. The branch-picker is also next to the breadcrumb — small click target.
4. **No "Send" / "Stop" affordance separation in the composer when text is present mid-stream.** The button silently switches semantics from Send to Queue based on streaming state. The tooltip explains it, but users may not notice the change.
5. **Connection card duplicates a "Connections" header**: the Settings page renders `<h2>Connections</h2>` at `settings.page.ts:23-25`, then `<app-feature-connections>` mounts ANOTHER `<h2>Connections</h2>` at `feature-connections.ts:30-32`. Confirmed user remark "Connexion affiché deux fois".
6. **Notifications "Send test notification" reaches the Rust side via `commands.emitMessageEndNotification`** which has its own gate (`if !prefs.desktop { return Ok(()) }`). Meanwhile, the real notification path in `core/notification.service.ts:35-44` uses `tauri-plugin-notification`'s JS API and explicitly handles permission. The Rust path doesn't request permission — so on first run (no permission granted yet), the test silently no-ops. **Real bug.**
7. **macOS window controls render at the top of the left sidebar** (`app-shell.ts:96-120`). User wants them at the right edge (right sidebar when present, top-right of the central column when not). Currently left-aligned.
8. **Sidebar `[+ Add a project]`** opens an `app-feature-add-project` row whose options trigger the 3 dialogs directly — different from spec §3.3 which proposed routing to `/`. The router-to-`/` flow lives only on the empty state right-click menu. **Drift.**

## B2 — Phase 7 readiness

**Verdict : GO with IMP-001 as the only hard prerequisite.**

Phase 7's refactor + store work touches the `ProjectsFacade` and the
sidebar surface area (`shell-project-list.ts`, `ui-group-by-filter`).
IMP-001 (filter popover keeps full project list after filter) ships a
contract change : the popover consumes `facade.all()` instead of
`facade.visible()`. Resolving this in a single ½-day patch *before*
the Phase 7 refactor avoids merge conflicts and prevents the bug from
propagating into the new store API.

The other three blockers (IMP-002, IMP-003, IMP-004) are surface-level
moves — they don't touch the facade contracts and can ride along the
Phase 7 PR or land in a parallel small patch.

The Chat-removal ask (IMP-007) needs explicit user confirmation
before execution. If we do it, Phase 7's first atom should be "Chat
decommission" so the subsequent refactors don't churn around code that
will be deleted.

The Composer simplification (IMP-011 / IMP-014) is the natural
companion of Phase 7's UI-state-store work — bundle them.

Everything else (IMP-005…010, 012, 013, 015–022) is independent enough
to be slotted into a Phase 7 "polish" sub-phase or into Phase 8 alongside
the e2e tests.
