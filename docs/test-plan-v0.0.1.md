- Task description required (button disabled until non-empty)
- Submit → worktree created at `<repo>/.worktrees/<short_id>` with `agent/wip-<short_id>` branch
- Status transitions visible: initializing → running → done (or error/conflict/stopped)
- During running: tokens stream into center panel within 200ms of CLI emitting
- During running: send button shows Stop; clicking Stop kills CLI process within 1s
- Done state: diff appears in right panel automatically; "Discard changes" button visible

## Edge Cases

### Claude CLI auth
- CLI installed but old version (below pinned minimum) → onboarding shows "Update Claude Code" message with link
- `claude auth login` PTY closed by user mid-flow → onboarding returns to "Sign in to Claude" state without progressing
- CLI installed but `claude --version` exits non-zero → treated as "not installed", install link shown
- User has multiple `claude` binaries on PATH → use first match, document in Settings

### Worktree creation (D16 edge cases)
- Repo with LFS → workspace creation succeeds; warning banner: "LFS files appear as pointers in workspaces in v0.0.1"
- Repo with single submodule → `git submodule update --init` runs (no recursion)
- Repo with multiple submodules → workspace creation refused with `AppError::UnsupportedRepoFeature { kind: "complex_submodules" }`; clear error in UI
- Nested repo (`.git` folder inside selected repo) → workspace creation refused with explicit error
- Repo with detached HEAD → workspace creation refused: "Check out a branch first"
- Repo with dirty working tree → warning shown, creation proceeds (workspace based on HEAD, not staged changes)
- Branch name slug edge cases:
  - Task title with only special chars (e.g., `"!!!"`) → fallback to `agent/wip-<short_id>` (slug invalid)
  - Task title 200+ chars → truncated to 40
  - Task title with non-ASCII → non-ASCII chars become hyphens
  - Generated name fails `git check-ref-format` → fallback to placeholder name
- Worktree creation fails (disk full, permissions) → row removed, clear error surfaced

### Agent runtime
- Claude CLI subprocess crashes mid-stream → status=crashed, last partial output captured, exit_code stored
- User kills app mid-stream (cmd-Q) → tokio Child kill_on_drop fires, orphan cleanup at next launch removes stale workspace if needed
- Claude CLI emits no output for >60s → no special handling in v0.0.1 (timeout in v0.0.2)
- Claude CLI exits with non-zero but stdout had content → status=error, error_message includes exit code
- User clicks Stop while Claude is mid-tool-call → CLI receives SIGTERM, current operation may complete; capture state at exit
- Multiple Stop clicks → idempotent, no double-kill error

### Sandbox guardrails
- `git checkpoint` fails (e.g., no changes to commit) → `--allow-empty` flag handles; commit still succeeds
- `git diff` after run returns empty → WorkspaceChanges row written with all zeros, no error
- `discard_changes_to(sha)` when sha invalid → AppError::Worktree, user sees inline error
- User selects repo not under their home dir → no special handling in v0.0.1

### Telemetry
- PostHog 5xx response → outbox attempt count increments, exponential backoff
- Outbox reaches 10K events → oldest dropped (logged), new events still enqueued
- Telemetry toggle off → `track()` returns immediately (no-op, no DB write)
- App killed mid-drain → in-flight events stay in outbox, retry on next launch

### Tour
- First launch with no internet → bundled snapshot extracts, tour works offline
- Bundled snapshot extraction fails (corrupt tar) → tour disabled, "Try again later" message; user can still use Add Repo path
- Background clone succeeds, current tour in progress → swap deferred to next tour launch (don't yank state mid-flow)

### Web (Phase 2)
- Clerk session expires while on /downloads → AuthGuard redirects to /login on next route activation
- Clerk webhook callback URL drift → return to /login with error
- /downloads accessed without auth → AuthGuard blocks, redirects to /login

## Critical Paths (must work end-to-end)

### Phase 1 (desktop core, no web/landing)
1. **First-time install → first stream**: install binary → launch → onboarding all 4 screens → Claude CLI auth → choose "Add my own folder" → pick repo → create workspace → see first token in center panel
2. **Quickstart tour**: install → launch → onboarding → choose "Try demo" → tour 4 steps complete → land in shell with quickstart project loaded
3. **Workspace cycle with rollback**: create workspace → agent runs → diff appears → click "Discard changes" → workspace returns to base state, no lingering files
4. **Cancel mid-stream**: create workspace → agent starts streaming → click Stop → CLI killed within 1s → partial diff captured if any
5. **Follow-up message**: workspace done → user types follow-up → second agent_run starts in same thread, new run_id, conversation continues
6. **Edge case rejection**: try to create workspace from nested repo → clear error message, no orphan worktree left behind

### Phase 2 (web + landing + telemetry)
7. **Landing → Clerk login → download → install**: visit mozart.build → click download → redirected to app.mozart.build/login → GitHub OAuth → /downloads page → click correct platform binary → install → launch desktop → onboarding works
8. **Telemetry roundtrip**: install desktop → opt-in implicit (default) → complete onboarding → verify PostHog dashboard receives `onboarding.completed` event with anonymous device_id within 30s
9. **Telemetry opt-out**: install → see first-launch banner → click "Settings to opt out" → toggle off → no further events sent (verify PostHog count stops)

### v0.0.1 release gate (manual QA before tag)
10. **Cross-platform smoke**: critical path #1 works on macOS 14, Windows 11, Ubuntu 22.04 (manual)
11. **Unsigned install workarounds work**: macOS `xattr -cr` instructions on /downloads page actually unblock the binary; Windows "More info → Run anyway" works
12. **SHA256 verification**: every binary on /downloads page has SHA256 that matches `shasum -a 256 -c SHA256SUMS`
